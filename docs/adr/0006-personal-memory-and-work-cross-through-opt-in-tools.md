# Personal memory and Work reach each other only through opt-in, read-only tools

Chat and Work are no longer fully apart: personal memory and Work history are used when a task needs them. The person chose this rule after comparing ChatGPT, where ChatGPT Work shares the account's memory but Codex keeps a separate store that is off by default. Harness Work is a coding agent like Codex, so every crossing is narrow and starts off:

- **Memory Lookup.** Beluga registers a read-only tool, `personal_memory_lookup`, that returns Saved Memories and the Memory Summary to top-level Work agents. Harness tools have no per-session visibility condition, so the tool is registered only while the person has it on, and a tool guard refuses any call from a subagent or from PTC code, so delegated work cannot read personal memory in bulk. Custom Instructions never reach Work, which keeps its own AGENTS.md chain. Calls and results are logged in the Work session like any tool call.
- **Work Records.** An App in Chat reads Work sessions through `sessionQuery`, read-only and off by default. `sessionQuery` checks no caller, so Beluga reads only the workspaces the person allows. Beluga leaves the official `sessionQuery` configuration alone, and the daily web profile keeps full-text search off. Work Records therefore reads the newest top-level sessions of the allowed workspaces, at most `maxWorkSessions` per search, and matches the time range and words against what the person and the agent said; tool calls, reasoning and injected notices are never read. What it returns is tool output: it never counts as something the person said. A reply that read Work cannot propose a memory, and the Memory Summary skips what the assistant said after the read.
- **Nothing learns from Work.** No Work session feeds personal memory.
- **Hand-off to Work.** The person picks a workspace in Chat's hand-off dialog, because `uiWorkspace.startSession` alone uses the current workspace. The quiet model writes a brief from the chat without memory or Custom Instructions, and Beluga prefills a new Work session in that workspace, appending to a draft already there; the person sends it. Beluga still never creates, forks or deletes a Work session.

This amends ADR 0001's "Work remains unchanged": Work changes only when the person turns Memory Lookup on. A hard wall was rejected because daily use needs both directions, such as a status report written from today's Work or a coding task that should know the person's preferences. Automatic injection or learning was rejected because coding transcripts would flood personal memory and personal context would be added to every Work request.
