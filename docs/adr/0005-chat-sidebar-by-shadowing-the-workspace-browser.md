# Chat's sidebar shadows the workspace browser while Chat is open

Chat mode shows one sidebar whose navigation region lists Beluga's chats, while Work mode keeps the stock workspace browser. Beluga does this from its own client plugin, without patching Harness: while the Mode is Chat it registers its navigation in the single `sidebar.workspaces` slot at a priority below the stock entry, and disposes that registration when the person returns to Work, so the stock browser renders again unchanged. Beluga also adds a Work row to the panel list; selecting it returns to the Conversation view.

In Harness 0.2.1-rc.3 the stock New Session button is written into `SidebarRoot` with no extension point, so its label stays New Session in Chat mode. Its button, brand, title-bar control and `session.new` shortcut all call `uiWorkspace.startSession` without a target. While Chat's page is selected and the primary action below is absent, Beluga answers that call with New chat by defining `startSession` on the service instance itself, since a property assigned through a Cordis service proxy only reaches the caller's own shadow; it restores the instance on disposal. The answer is limited to Chat's page because Automation tasks' New task makes the same call. The stock browser remounts on each return to Work, keeping its stored view but not its search text or scroll position.

A patched Harness was rejected because the person would have to carry the patch across every Harness upgrade beside the Beluga repository. Deep imports of `ui-sidebar` or `ui-workspace` internals were rejected because those files are not exported and change between releases. Beluga depends on the `sidebar.workspaces` slot name, its `wide` and `expandSidebar` props, single-slot priority shadowing and, without the primary action, the `uiWorkspace.startSession` method, which each Harness upgrade must be checked against. If Harness publishes seats that let the selected panel supply the sidebar's navigation and primary action, Beluga moves to them and drops the shadowing.

Harness adds a sidebar primary action registry, `ctx.sidebarPrimaryAction`, whose fallback is New Session; the sidebar button, the macOS title-bar control, the brand and `session.new` all run the active registration. Beluga waits for that service with `ctx.inject`. While it exists and the Mode is Chat, Beluga registers New chat at a priority below the default, disabled with a reason while Chat is busy, and removes New chat from its own region, so Chat mode has one primary action. The region and that registration both follow the Mode rather than the selected panel: Plugins and other Harness pages keep Chat's region and New chat, and running New chat or opening a chat from there selects Chat first. Harness 0.2.1-rc.3 does not provide the service, so on it the inject never runs and the New Session answer above carries New chat instead; the region lists New chat only when neither exists. Beluga declares the service's `Context` property itself until it builds against a Harness that declares it, and then deletes that declaration.
