# Office 迁移开发进度

## 当前候选：PPT 生成 P0（2026-11-08）

**新增：**
- `create_presentation`：用 8 种固定版式生成 16:9 演示文稿：封面、章节、要点、两栏、图表、表格、关键数字、图片。模型只给内容，位置和字号由引擎决定。
- 内置主题：主色 `#1F4E79`，西文 Calibri，中文 Microsoft YaHei。所有文字引用主题字体，标题放在标题占位符里。
- 文字适配：中日韩字符按 1 em、其他字符按 0.55 em、行高按 1.32 em 估算。标题从 32 pt、正文从 22 pt 起每次缩小 2 pt，最小 24 pt 和 16 pt。还放不下时照常交付，在 `check.issues` 里按页和区域报告 `overflow`。
- 图表是原生图表，数据在内嵌工作簿里。柱状图和条形图在没有负值时从 0 开始，数值带千分位；饼图和环形图显示百分比。表格的数字列右对齐，表头有底色。
- 图片只取本分支上附加的 PNG 或 JPEG，宿主读出字节后传给引擎，链接和路径会被拒绝。模型现在能看到图片附件的 `attachmentId`，和文档附件一样。
- 保留演讲者备注。文件属性的作者写为 Beluga。
- 修复：读取用了 PowerPoint 分节的 PPTX 时报 `Missing or external Office relationship`。分节列表在扩展区里把幻灯片再列一遍，且不带关系 id；读取原来按名称匹配所有 `sldId`，现在只取演示文稿自己的幻灯片列表。
- 生成库是 pptxgenjs 4.0.1（精确锁定）。生成后，项目符号和图表里的 Arial 改为引用主题字体，主题补上中文字体；备注母版用自己的主题；`[Content_Types].xml` 只声明存在的部件。

**验证：**
- 360 项测试通过：新增 `presentations.spec.ts` 的 19 项（输入上限、文字估算、生成的 XML、引擎打开和导出），以及 `runtime.spec.ts` 的 3 项（经本地 inline 图片路由生成带图片的 8 页演示文稿；拒绝链接、路径、未附加和非图片的附件；临时聊天）。逐项改坏实现（主题字体、标题对齐、从 0 开始、数字列对齐、内容类型、备注母版主题、图片 id），对应测试都会失败。
- 引擎打开 8 页合成预算演示文稿：8 页，中文可见，没有缺失字体；230,000、235,000、5,000、2.17% 与 Word、Excel 产物一致。
- 隔离 profile 中用打包后的扩展走完整链路：7 秒生成 7 页（图片版式需要 inline 路由，由运行时测试覆盖），运行中显示“正在制作演示文稿”；预览、下载、导出 PDF（7 页）都正常，没有页面错误；1280 px 和 390 px 宽度下预览不溢出，关闭按钮可以点到。

**已知限制：**
- 没有在真正的 PowerPoint 或 Keynote 中打开过。pptxgenjs 的问题报告（1443、1449）里，有用户在 Mac 版 PowerPoint 打开 4.0.1 的输出时看到修复提示，原因没有定论。有依据的两项（备注母版共用主题、多余的母版声明）已修正；`presentation.xml` 的元素顺序按 pptxgenjs 原样保留，因为改成 schema 顺序的文件据报在 Mac 版打不开。
- 不能修改已有 PPTX（P1）；版式固定，不能自由摆放。
- 图片要经 inline 图片路由才能发送，所以只有选了图片模型时才能用图片版式。
- 估算按 Microsoft YaHei 和 Calibri 的字宽；本机预览用替代字体，排版可能与 PowerPoint 略有不同。
- 真实模型选择版式和写作的质量还没有验收。

## Excel 原生图表与打印适配（2026-11-08）

**新增：**
- `create_workbook` 和 `edit_workbook` 增加 `charts`：柱状图、条形图、折线图和饼图。图表引用本工作表的单元格，数据改了图表跟着变；上传的工作簿也能加。
- 图表自动放在数据右侧，空一列；同一工作表的多个图表依次往下排，不压住已有的图片和图表。
- 系列名默认引用表头单元格。数字格式取源单元格，所以 `#,##0` 在坐标轴上显示千分位。
- 柱状图和条形图在值都非负时从 0 开始；有负值时坐标轴自动，类别标签放在最低处。
- 图表在重算之后写入，缓存是计算后的值。临时聊天不计算，公式结果留空，Excel 打开时会计算。
- `check.charts` 报告每个图表的位置，以及不是数字的值单元格。
- 新建工作表打印时缩放为一页宽；超过 6 列或带图表时横向。
- 文件预览对话框最宽 920 px，窄屏时占满可用宽度。之前宽度设在 380 px 卡片里面的内容区上，宽的工作表图片和关闭按钮会被裁掉。

**验证：**
- 338 项测试通过：新增 `workbook-charts.spec.ts` 的 12 项，以及 `runtime.spec.ts` 中创建、修改时都加图表的一项。
- `scripts/ooxml-schema-check.py` 按 ECMA-376 第 4 部分的过渡 schema 校验手写的图表、绘图和工作表部件，全部有效；故意改坏的副本会被拒绝。
- LibreOffice 往返后图表仍在；openpyxl 读到正确的类型、锚点和引用。
- 隔离 profile 中用打包后的扩展走完整链路：创建、预览、下载、导出 PDF，没有页面错误。预览和 PDF 的坐标轴显示千分位；在 1280 px 和 390 px 宽度下，预览图片完整可见，关闭按钮可以点到。

**已知限制：**
- 不能修改或删除已有图表。修改单元格后，已有图表的缓存不刷新；Excel 和 LibreOffice 打开时按单元格重画，只读缓存的程序会看到旧值。
- 预览只显示前 60 行，往下排的第 4 个图表会被截掉。
- 日期、时间、货币和会计等随地区变化的内置格式，坐标轴退回 `General`。
- 没有在真正的 Excel 或 Numbers 中打开过；真实模型如何选择图表还没有验收。

## Word 和 Excel 专项（2026-11-07）

**接入的官方能力：**
- Harness 自带的 `@deepseek-ai/libreoffice-kit` 负责预览、导出 PDF 和重算。Office 扩展把它声明为 peer，不再下载约 146 MB 的引擎，也不会被 `koffi` 的构建脚本拦下。
- `docx` 负责 Word 生成和模板填充；ExcelJS 只用于新建工作簿。

**新增工具：** `read_sheet`、`create_workbook`、`edit_workbook`、`edit_document`、`fill_template`。`create_document` 增加 `html`、`chart`、`toc`、`pageBreak`，默认带页码，可设页眉。

**移除：** `inspect_document`、`revise_document` 和 `personal_chat_documents` 表。`edit_document` 能直接改任何 DOCX，不再需要保存生成时的结构。存储升到 v4，升级时删除这张表；文件本身不受影响。

**模型能看到的结果：**
- `edit_workbook`、`create_workbook` 返回 `check`：是否重算、公式数、错误单元格、引擎不支持的函数。
- Word 工具返回 `check`：文件能否打开、页数、缺失字体。
- 工具失败时带上具体原因，模型可以自行改正，例如段落已变化、合并单元格不能改。

**已知限制：**
- 重算结果来自 LibreOffice，个别函数和 Excel 可能不同。不支持的函数保留原值并列入 `unverified`。
- 预览是 LibreOffice 的版面，和 Word、Excel 可能略有差异。生成文档使用 Calibri 和微软雅黑，Linux 预览会提示缺字体。
- `HYPERLINK` 公式没有拦截：它和聊天里的链接一样，要用户点击才会发出请求。
- 只在 Linux 的 WASM 引擎上确认过不联网；macOS 和 Windows 的原生引擎未验证。
- `edit_workbook` 不能增删工作表或行列，不改合并区的非首格、表格表头和数组公式。`edit_document` 不能增删表格。
- 没有在真实 Word 和 Excel 中打开过产物。独立复核用的是 python-docx、openpyxl 和 LibreOffice。

## Word 生成与修订

- `create_document` 用受限标题/正文/表格结构生成可编辑 DOCX；`inspect_document` 读取源块；`revise_document` 只替换指定的零基块索引。
- 源块仅适用于本插件生成的 Word；上传模板尚不能通过此路径编辑。
- 每次修订产生新附件 ID，保留根产物、父版本和修改摘要。文件卡区分输入原件与产物版本。
- 生成字节暂存内存，工具结果与附件引用一起发布；停止或提交失败不会发布新版本。临时源块和文件均不写持久库。

- 可视检查合成 Word：中文、表格和 230,000 / 235,000 / 5,000 / 2.17% 正常，无缺失字体。该渲染使用独立验收脚本，尚不是聊天内预览。
