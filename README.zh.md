# 白鲸 Beluga

DeepSeek Harness 的个人 Chat 插件，名字来自最爱“说话”的鲸鱼之一。

[English](README.md)

用一个插件，在 Harness 的 Work 旁增加个人 Chat、ChatGPT 历史导入、用户画像和可控记忆。Chat 不要求选择仓库，也不会把个人聊天伪装成 Work 执行记录。

Chat 插件基础安装仅提供 **Chat 与 Memory**（含历史导入等已有能力）。**Word／PPT／Excel 办公扩展推荐但不预装**：必须由用户明确同意后，单独下载并启用 `dsh-beluga-office`。基础包不依赖办公包，也不包含其文件处理库；模型和上传文件均不能触发自动安装。

## 从源码构建

目前还没有发布好的 tarball 或 npm 包，需要用 Node 24.9+ 和 pnpm 自行构建：

```sh
git clone https://github.com/Subaru486desuwa/dsh-beluga.git
cd dsh-beluga
pnpm install --frozen-lockfile
pnpm run build
pnpm run pack
```

tarball 生成在 `dist/`，下面的命令请换成对应路径。

## 安装构建好的插件

目标版本：**未修改的 DSH 0.2.1-rc.3**，Node **24.9+**。当前是发布前候选版，尚未发布到 npm 或公共插件市场。

将构建好的 tarball 安装到所选 **web** profile，再重启该 profile：

```sh
dsh plugin --profile web add ./dsh-beluga-0.1.0.tgz
dsh --profile web
```

从 Harness 侧栏打开 **Chat** 即可聊天。聊天左上角显示聊天标题：第一次回复后，模型会根据第一轮对话写一个简短标题，只写一次，你改过名就不会再改，之前的聊天保留原标题（`autoTitles` 可关闭）。输入框右侧的按钮显示所用模型和思考强度：点开后拖动滑条调整强度，点模型名换模型。打开 Chat 时，侧栏原本显示工作区列表的位置改为显示你的聊天：置顶的在最上面，其余按日期分组，也可以在排序菜单里改为按状态排列（进行中、等你处理、有新回复）。转圈表示正在回复，圆圈表示在等你处理（等你批准操作，或有待确认的记忆），圆点表示回复是在你没打开这个聊天时完成的。搜索也能找到已归档的聊天，并标出“已归档”。列表底部的 **设置** 打开一个对话框，分为通用、个性化、应用和数据管理。Chat 上方的 **Work** 行返回原工作界面，保留原先选中的工作会话；顶部的 New Session 按钮仍会新建 Work 会话。插件只增加自己的配置项，不替换官方模块、不修改 Harness 核心。

## 聊天与文件

- 流式回复、停止、复制；编辑用户消息或重新生成回复时保留旧分支。
- 长对话的完整历史始终可见。聊天超出一次模型请求能带的量时（`maxContextBytes`，默认 512 KiB，上下文窗口更小的模型会更少），先不带较早的工具结果，再由模型在后台把最早几轮压缩成摘要，之后的回复仍然知道这些内容。
- 搜索标题和正文，重命名、归档、删除聊天及其附件。归档只是把聊天从列表里隐藏：搜索仍能找到，模型仍能搜到，也仍会写进记忆摘要；删除才会让 Beluga 忘记它。已归档的聊天在 **设置 → 数据管理** 里打开、取消归档或删除。
- 置顶聊天；把聊天导出为 Markdown。工具输出和推理内容不会导出。
- 回复下方列出它的来源：参考的网页、用到的已保存记忆、搜到的过去聊天（点击打开）、读过的 Work 会话（点击在 Work 中打开）。记忆摘要和自定义指令每次都会带上，不逐条列出。朗读只使用设备上的语音，没有本机语音时会提示，不会把文本发给语音服务。
- 上传文本、可提取文字的 PDF 和图片；扫描 PDF 需要先在外部 OCR。图片需要下方的独立内联模型配置。
- 用户安装办公扩展后：DOCX／XLSX／PPTX 支持结构化读取，工作表可按区域读取；Office 文件可在本机预览和导出 PDF；可生成带列表、表格、图表、目录、页码和中文字体的 Word；可定点修改任意 DOCX（含上传文件，可选修订痕迹）并填充 `{{名称}}` 模板；可新建 Excel，定点修改任意 XLSX（含上传文件），其他内容不变，公式会重算并报告 `#REF!` 等错误。每次修改生成新版本并保留原件。Chat 不执行代码，拒绝会联网或启动程序的公式。临时聊天只在内存处理文件，没有预览、PDF、重算和版面检查。PPT 生成尚未提供。
- Harness 配置了网页服务时，模型会在需要时自动搜索网页。可在 **设置 → 应用** 关闭自动使用，之后只有从 + 菜单选了 **网页搜索** 的消息才会搜索。Chat 不开放终端、任意文件系统或部署工具。

## 导入 ChatGPT 历史

打开 **设置 → 数据管理 → 导入 ChatGPT** → 选择官方 ZIP 或对话 JSON → 核对数量与警告 → **导入**。

ZIP 可以远大于上传上限：浏览器只读取其中的对话 JSON（单个 `conversations.json`，或编号的 `conversations-000.json` 等分片）并上传这部分，媒体留在本机。

保留原始 JSON、未知字段、角色、时间、完整 `mapping` 分支图和 `current_node`。可切换任意原分支查看。语音消息按其转写文字导入。原档案中的媒体引用会保留，但不导入 ZIP 内媒体文件，也不会自动下载外链图片。思考过程同样保留在原档案中，但不进入历史视图、Markdown 导出和模型上下文。重复内容跳过，变化的内容保存新修订；撤销导入只移除该批次的档案，不删除之后继续聊的内容。

直接在所选历史分支下继续聊天。模型获得有大小上限、明确标注为不可信历史的上下文；被省略的节点会提示，完整原档案仍可查看。

默认上限：上传 64 MiB（ZIP 按去掉媒体后计算）、解压后对话 JSON 256 MiB、10,000 条对话、总计 500,000 个节点、已存档案 512 MiB。遇到不支持或损坏的记录时，预览会整体拒绝，不悄悄丢弃。已用 2026 年 11 月的一份真实官方导出验收；仓库内测试数据仍全部为合成数据。其他导出可能有差异。

## 个性化与记忆

**设置 → 个性化** 管理自定义指令（关于你、回复偏好）、记忆开关、记忆摘要，以及已保存的记忆和待确认项。开关改动后立即保存。自定义指令不依赖关键词召回。只有范围很窄、能追溯到用户原话的低风险偏好可自动保存；敏感、推断和冲突信息需要确认。回复提出的记忆就地显示在这条回复下方：自动保存的可以撤销，待确认的可以保存或不保存，未处理前聊天在列表里显示为等你处理；其他聊天自动保存的记忆另有提示和撤销入口。纠正会替代旧事实，忘记会阻止从相同文本或旧证据自动重新学回。

**记忆摘要** 是模型根据你的普通聊天写下的关于你的概述：聊天空闲后自动更新，两次自动更新至少间隔 6 小时，之后的普通聊天会把它当作背景。临时聊天和导入历史不会写进去。它只记录你自己说出或确认的内容；你让助手写的稿件、翻译和角色扮演、你粘贴的文字以及假设，都不会被当作你的观点。每次更新只改需要改的那几节，其余各节一字不动。在它的菜单里选 **编辑**，可以自己修改，或粘贴一份已有的摘要。保存时不经过模型，按原样写入，只会移除密钥、长串数字和邮箱地址。**恢复上一版** 可以撤销最近一次修改。

可先预览再导入已保存记忆的文本／JSON，以及个人指令 Markdown。导入 `AGENTS.md` 时需检查内容是否属于个人范围；插件不会修改源文件或 Work 规则。不要导入凭据。对话 ZIP 不会自动还原 ChatGPT 单独的已保存记忆库。

回复时，模型可以搜索你过去的聊天并引用片段，这些片段会发送给所选模型服务。可在个性化里关闭。临时聊天和导入的原始历史不会被搜索，已归档的聊天会：导入历史只有在续聊时才会发送给模型。忘记一条记忆不会删除记录它的聊天，模型仍可能从那段聊天里搜到；需要时请删除该聊天。

## 与 Work 互通

Chat 和 Work 默认互不读取。**设置 → 应用 → Work** 里有两个开关，可分别打开：

- **让 Work 查询个人记忆**：每个 Work 会话的主 agent 会多一个只读工具 `personal_memory_lookup`，可以读取已保存的记忆和记忆摘要（可按关键词过滤），读不到自定义指令和“关于你”。subagent 或 PTC 代码中的调用会被拒绝。调用和结果像其他工具调用一样记在 Work 会话里。
- **在聊天里读取 Work 记录**：勾选允许的 workspace 后，聊天模型可以按时间和关键词查找这些 workspace 中由你发起的 Work 会话，并读取你和 agent 说过的话；工具调用、推理和 Harness 插入的提示不会读出。每次查找最多读取最近 50 个会话（`maxWorkSessions`），不需要开启 Harness 的全文会话搜索。回复下方会列出读过的 Work 会话，点击即可在 Work 中打开。读到的内容只是工具输出：读过 Work 之后，这条回复不会再提议记忆，记忆摘要也会跳过助手随后说的话。

在聊天菜单（临时聊天在标题栏）里点 **交给 Work**，选择一个 workspace 后，模型会根据这段聊天写一份任务简述（不带记忆和自定义指令），放进该 workspace 新 Work 会话的输入框，由你检查后发送；输入框里已有草稿时，简述会追加在后面。Chat 从不自己创建或发送 Work 会话。

## 临时聊天

消息和附件仅保留在内存，不读取／写入画像和长期记忆，不进入历史，也不保存浏览器草稿。离开页面即关闭；断线后无人查看的临时聊天按配置超时清理，默认 60 秒。宿主重启后不保留。

所选模型服务仍会收到请求，适用其自身的数据保留政策。用户另装的 Harness 观察插件与操作系统转储不属于本插件的存储边界。文本调用不设置 Work `sessionId`，图片绕开宿主的持久上传流程。

## 可选：内联图片模型

文本复用 Harness 模型路由。图片需要一个接受内联图片的 OpenAI-compatible Chat Completions 接口，以及**已有 Harness 凭据引用**，不要在配置中写 API key。修改所选 profile 的 patch：

```yaml
- id: personal-chat
  config:
    dataDir: !!js dshHomePath('personal-chat')
    inlineProvider:
      baseURL: https://YOUR-PROVIDER.example/v1
      credentialRef: YOUR_EXISTING_CREDENTIAL_REFERENCE
      models: [YOUR_IMAGE_MODEL]
```

选择带 **Inline images** 标记的模型。它使用提供商 API，不等同于 ChatGPT 网页订阅。rc.3 原生图片流程会落盘，因此这里采用独立内联路径。协议与载荷由本地 HTTP fixture 验证；具体真实提供商／模型组合仍需单独验收。

## 数据与卸载

插件数据在 `$DSH_HOME/personal-chat`：私有 SQLite 数据库及附件。备份时先停止该 profile。删除聊天会清理其历史和附件，但单独确认过的记忆仍保留，需要在 **设置 → 个性化** 里另行忘记。卸载不删除个人数据：

新版本首次启动时会就地升级数据库，升级后旧版本插件无法读取，请先备份。

```sh
dsh plugin --profile web remove dsh-beluga
```

多个 profile 同时运行时应使用不同 `dataDir`；写入锁会阻止多个实例共用同一数据库。

## 按需安装办公扩展

确认愿意下载办公依赖并启用文件处理后，再在已安装 Chat 的同一 profile 执行：

```sh
dsh plugin --profile web add ./dsh-beluga-office-0.1.0.tgz
```

重启该 profile 后生效。扩展直接使用 Harness 自带的引擎，不会再下载大文件。未安装时可保管和下载 Office 原件，但不会向模型提供办公生成或编辑工具。卸载办公扩展只停止处理能力，保留聊天、记忆和已有产物下载：

```sh
dsh plugin --profile web remove dsh-beluga-office
```

两个包目前均未发布到公共市场；上述路径指自行构建或明确取得的 tarball。
